# CLAUDE.md

Контекст проекта. Читай перед любой правкой и перед записью дня в журнал.

## Что это

Личный геймифицированный трекер «Система». Владелец переучивается из проджект-менеджера
в продакта. Приложение показывает навыки как уровни RPG (1-100), физическую форму,
недельную активность и квесты трёхнедельного спринта. Деплой на Vercel, PWA на телефоне.

## Источник правды

`data/days.json`, массив записей `DayRecord` (см. `src/engine/types.ts`). Движок
(`replay()` в `src/engine/engine.ts`) пересобирает персонажа из журнала с нуля при
каждой загрузке. localStorage держит только черновик текущего дня.

Записи в журнал пишут два канала: телеграм-функция `api/telegram.ts` (Gemini разбирает
текст) и Claude напрямую через git. Оба должны считать XP по ставкам из
`src/engine/rules.ts`, никаких своих ставок.

## Главный принцип механики

Уровень нужно оплачивать. У каждого навыка есть содержание (`dailyUpkeep`), XP в день
просто за удержание уровня. Заработал меньше, разница уходит из опыта. Это центральная
идея, не баг.

Пропущенные дни не бесплатны: `replay()` закрывает каждый календарный день от первой
записи до вчерашнего включительно, а день без записи закрывается с нулём. Молчание стоит
уровней.

Ограничители, которые нельзя тихо выкинуть при рефакторинге:
- Пол: уровень не падает ниже пика минус `LEVEL_FLOOR_MARGIN` (15).
- Заморозка (`frozen`): останавливает и списание, и начисление.
- Калории: XP только за попадание в коридор. За недоед бонуса нет и быть не должно.
- Вес: показывается как тренд, XP не даёт и не отнимает.
- Квест `workout` закрывается только силовой, кардио-сессией или секцией. Прогулка и шаги
  дают fit-XP, но квест не трогают.
- Поле `quests` двигает только прогресс спринта, XP повторно не начисляет.

## Сезоны

Запись с полем `season` перезапускает персонажа на эту дату: навыки к стартовым уровням,
квесты в ноль, спринт заново, скользящие логи очищены. История до неё остаётся. Чистый
маркер (без XP) содержание не списывает. Используется после долгих пауз вместо
персонажа, которого заполнение дыр стёрло до пола. Текущий: сезон 2 с 2026-11-01.

При замене записи за дату, на которой стоит маркер, поле `season` надо сохранить.

## Даты

День считается по Asia/Almaty (`todayStr()` в engine.ts), не по UTC. Запись за сегодня
накладывается как черновик и закрывается завтра.

## Архитектура

```
src/engine/rules.ts     весь баланс: кривые уровней, содержание, ставки, квесты
src/engine/engine.ts    replay, closeDay, сезоны, deriveView
src/engine/types.ts     DayRecord, GameState
src/engine/store.tsx    replay(journal) + черновик дня из localStorage
src/components/         только рендер, без логики
api/telegram.ts         вебхук Telegram → Gemini → GitHub Contents API
api/tsconfig.json       nodenext: относительные импорты с .js, как требует рантайм Vercel
data/days.json          журнал
```

Правишь баланс: только `rules.ts`, без магических чисел в JSX. Новые зависимости не
добавлять без веской причины. Перед коммитом: `npm run build` и
`npx tsc -p api/tsconfig.json --noEmit`.

## Как записать день (для Claude)

1. Прочитай `rules.ts` (ставки, квесты) и `data/days.json`.
2. Собери `DayRecord` за сегодня по Алматы: `date`, `note` (3-6 слов), `xp {pm, prod, disc}`,
   `fit`, `quests` (только реально выполненные), `sleep`, `calories`, `mood`.
   Неназванное оставляй пустым, не угадывай.
3. Запись с той же датой заменяй, не дублируй. Массив сортируй по дате.
4. Коммит вида `День 2026-11-02: PM +90, DISC +25`, пуш в main. Vercel передеплоит сам.

## Тон интерфейса и сводок

Приборная панель, не тренер. Без восклицательных знаков, лозунгов и стыда за пропуск.
Падение уровня сообщается сухо: «PM 60 → 59». Длинные тире не использовать.
